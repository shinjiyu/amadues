# 广告公司目标客户智能系统 — 需求规格说明

> **版本**：v0.2（讨论草案，含 AI 零知识启动）  
> **状态**：仅文档，待业务方评审  
> **关联目录**：[README](./README.md) · [架构草案](./architecture-draft.md) · [开放问题](./open-questions.md)

---

## 1. 背景与动机

### 1.1 现有资产

| 资产 | 说明 | 系统侧期望 |
|------|------|------------|
| **内部广告案例** | 历史项目、创意、渠道、投放结果等；**已有数据源**（库表/文件/BI 等，形态待确认） | 作为筛选与方案生成的**知识库**与**相似度/效果参照** |
| **目标客户名单** | 希望拓展或重点跟进的客户列表 | 作为**工作队列**与 enrichment 的**种子集** |

### 1.2 业务痛点（推断）

- 案例分散，销售/策划难以快速找到「和某客户最像的成功项目」。  
- 名单上的客户信息不完整，合作史、投放数据散落在 CRM、邮件、表格中。  
-  prioritization 依赖经验，缺少统一的 ROI 预估与可解释排序。  
- 方案撰写重复劳动大，希望用案例 + 数据做**结构化起稿**。

### 1.3 总体目标

构建一套 **AI 优先** 的系统（或平台），在**合规与权限可控**前提下：

1. **聚合**目标客户与关联实体的情报（**支持零知识启动**：仅公司名即可由 Agent 探索信源）；  
2. **量化**客户优先级（以 ROI 为核心排序维度；冷启动可无内部案例库）；  
3. **生成**针对头部客户的营销方案初稿，供专业人员修改定稿。

### 1.4 AI 与「零知识启动」原则

| 原则 | 说明 |
|------|------|
| **AI 执行，人审核** | 探索、抽取、排序理由、方案起稿由 Agent 完成；敏感/无引用事实默认进审核 |
| **零知识 ≠ 零配置** | Day 0 不需 CRM/案例 mapping；Policy（域名、预算、是否自动入库）仍需一次性配置 |
| **信源越用越准** | AI 发现的域名经批准进入 `source_registry`，减少重复搜索 |
| **内部数据是加速器** | 案例库、CRM 接入后提高置信度，不替代公网探索流程 |

技术细节见 [tech/04-ai-zero-knowledge.md](./tech/04-ai-zero-knowledge.md)、编排选型 [tech/05-workflow-vs-agent.md](./tech/05-workflow-vs-agent.md)。

### 1.5 编排原则（不直连 LLM API）

| 项 | 说明 |
|----|------|
| 业务代码 | 仅通过 **编排客户端** 触发 Agent / Workflow（推荐 Dify HTTP API） |
| Agent | 仅 **情报探索**（动态选 URL / 搜索词） |
| 工作流 | 打分、方案生成、事实校验、单页抽取、批处理 |
| 模型密钥 | 只配置在 **编排平台** 与 `tools-service`（若工具内无 LLM 则无密钥） |

## 2. 总体目标与非目标

### 2.1 本期目标（产品级）

| 维度 | 说明 |
|------|------|
| **客户情报层** | 以名单客户为主键，挂载公司信息、历史合作、投放/效果数据、行业与竞品线索等 |
| **案例知识层** | 内部案例可检索、可打标签，支持与客户的**相似匹配**与**效果引用** |
| **筛选与排序** | 可配置筛选条件 + ROI 排序 + 排序理由（可解释性） |
| **方案生成** | 对 Top N 客户输出结构化方案草案（目标、受众、渠道、创意方向、预算区间、KPI） |

### 2.2 非目标（首期建议明确不做或降级）

| 非目标 | 说明 |
|--------|------|
| **全自动对外投放** | 系统产出方案与素材建议，**不**直接操作广告平台账户（除非二期明确集成） |
| **无授权的大规模爬取** | 公网信息采集需遵守 robots、隐私与商务合规；默认 **人工审核入库** |
| **替代 CRM** | 可与 CRM 双向同步，但不强求成为唯一客户主数据系统 |
| **100% ROI 预测精度** | ROI 为**排序与决策辅助**，需标注置信度与数据缺口 |

## 3. 术语

| 术语 | 含义 |
|------|------|
| **目标客户（Prospect）** | 名单中的法人或品牌主体，系统内稳定 `prospect_id` |
| **案例（Case）** | 公司内部历史广告项目记录，含创意、渠道、预算、效果指标 |
| **合作史（Partnership）** | 该客户（或其关联公司）与**任意代理/品牌方**的历史合作记录（不限于本公司） |
| **投放数据（Campaign Metrics）** | 曝光、点击、转化、CPA、ROAS 等；来源可为公开报告、客户披露、第三方工具 |
| **ROI 得分** | 用于排序的综合指标，定义见 §5（需业务确认口径） |
| **方案包（Proposal Pack）** | 针对单一客户生成的营销方案文档结构（Markdown/PPT 大纲/JSON） |

## 4. 功能需求

### 4.1 模块一：目标客户信息收集

#### 4.1.1 数据接入（零知识最小集）

- **名单导入**：CSV **可仅含公司名**；可选 uscc、行业、地区作为加速 hint。  
- **AI 探索（默认路径）**：Agent 自行生成检索计划、发现信源、抓取并抽取事实，**每条事实带 URL 引用**。  
- **案例库 / CRM（加速器）**：有则合并入库，无则不阻塞启动。  
- **增量更新**：「重新探索」单客户；已批准信源优先复用。

#### 4.1.2 情报 enrichment

| 情报类型 | 示例字段 | 采集方式 |
|----------|----------|----------|
| 工商/主体 | 注册资本、成立时间 | **AI 读公网页**；有 API 时加速器覆盖 |
| 历史合作 | 合作品牌、年份 | **AI 新闻/官网**；案例库反查 |
| 投放与效果 | 渠道、花费线索 | 报道摘录（标 estimated）；禁止无引用硬数字 |
| 营销动态 | campaign、代言人 | AI 探索 + citation |
| 竞争格局 | 竞品 | AI 归纳；敏感表述进审核 |

#### 4.1.3 质量与治理

- **来源标注**：每条事实带 `source`、`collected_at`、`confidence`。  
- **冲突处理**：多源不一致时保留多版本或进入「待审核」队列。  
- **权限**：按角色可见字段（如联系人电话仅销售可见）。

#### 4.1.4 验收标准（草案）

- 名单内 **≥80%** 客户可生成「最小档案」（公司名 + 行业 + ≥1 条可追溯来源）。  
- 销售可在 UI 内查看档案时间线并 **一键触发刷新**。

---

### 4.2 模块二：基于案例与数据的客户筛选（ROI 排序）

#### 4.2.1 筛选

- **硬筛选**：行业、地域、规模、是否已有合作、黑名单等。  
- **软筛选**：与某类案例的相似度阈值、最低预测 ROI 等。

#### 4.2.2 排序

- 默认按 **ROI 得分降序**；支持次要键（如案例相似度、战略客户标签）。  
- 列表展示：**得分、置信区间、关键因子贡献**（可解释性）。

#### 4.2.3 案例匹配

- 对每个 Prospect 推荐 **Top-K 相似案例**（行业、受众、渠道、预算量级）。  
- 匹配理由可读（非黑盒）：例如「同行业美妆 + 短视频种草 + 预算 500–800 万」。

#### 4.2.4 验收标准（草案）

- 业务方能对 Top 20 列表完成 **盲评**：≥70% 认为「合理可跟进」（指标可后续校准）。  
- 任意客户可展开「为何排在此位」说明。

---

### 4.3 模块三：头部客户广告营销方案设计

#### 4.3.1 触发与范围

- 对排序 **Top N**（可配置，如 10）或人工勾选客户生成方案包。  
- 支持 **批量生成** 与 **单客户深度生成** 两种模式。

#### 4.3.2 方案结构（建议固定模板）

1. 客户与机会摘要（基于情报层）  
2. 目标与 KPI 建议（参考相似案例效果）  
3. 受众与洞察假设  
4. 渠道组合与预算区间（引用案例区间）  
5. 创意方向与参考案例链接  
6. 时间线与里程碑  
7. 风险与待确认问题（数据缺口清单）

#### 4.3.3 人机协作

- 生成物为 **草案**；策划可在线编辑、版本对比、导出 Word/PPT。  
- **禁止** 在无依据时编造投放数据；缺口必须在文中标明。

#### 4.3.4 验收标准（草案）

- 资深策划对单份方案 **节省 ≥40% 起稿时间**（需试点测算）。  
- 方案中引用的案例 ID 均可回溯到案例库原始记录。

## 5. ROI 口径（待业务确认，技术需预留多模型）

建议提供 **至少一种** 可配置公式，并在 UI 显示「计算方式」。

### 5.1 候选定义

| 模型 | 公式思路 | 适用数据 |
|------|----------|----------|
| **历史 ROAS** | 基于本公司对该客户/同行业案例的 ROAS 加权平均 | 有真实投放结案 |
| **预估 LTV / CAC** | `(预估客单价 × 转化率 × 复购系数) / 预估获客成本` | 仅有行业 benchmark |
| **案例迁移分** | `相似案例 ROAS × 相似度 × 行业修正系数` | 新客户无历史 |
| **战略加权** | 上述得分 × 战略系数（大客户、窗口期） | 销售政策 |

### 5.2 置信度

- 数据完整度高 → 置信度高；缺投放数据 → 降级为案例迁移分并标黄。  
- 排序时可选项：**「高置信优先」** 而非单纯高分优先。

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| **安全** | 客户与案例数据加密存储；操作审计；导出审批 |
| **合规** | 个人信息最小化；跨境数据需单独评估 |
| **性能** | 名单 1 万级：批量打分夜间完成；单客户刷新 < 分钟级（视外部 API） |
| **可观测** | enrichment 任务成功率、生成方案 token/成本、人工采纳率 |
| **集成** | 预留 Webhook / API 供 CRM、飞书、钉钉通知 |

## 7. 用户角色

| 角色 | 主要动作 |
|------|----------|
| **销售** | 维护名单、查看排序、发起方案、反馈成交结果 |
| **策划** | 审核/编辑方案、维护案例标签 |
| **数据/运营** | 配置 ROI 规则、数据源、任务监控 |
| **管理员** | 权限、审计、模型与 Prompt 版本 |

## 8. 分期建议

| 阶段 | 范围 | 周期（粗估） |
|------|------|--------------|
| **P0 PoC** | 名单导入 + 案例库只读检索 + 手工补情报 + Excel 导出排序表 | 2–4 周 |
| **P1 MVP** | 自动 enrichment（1–2 个可信数据源）+ ROI 排序 + 单客户方案生成 | 6–10 周 |
| **P2** | CRM 同步、批量方案、监测回流、A/B 验证排序质量 | 按需 |
| **P3** | 广告平台只读拉数、素材库、结案数据反哺 ROI 模型 | 按需 |
