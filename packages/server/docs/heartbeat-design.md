# 心跳检测机制设计文档

## 1. 概述

心跳检测是"不死 agent"的第一层防线。环境侧定期拉取 agent 的外部可观测行为快照，与上一次比对；连续 N 次无变化则判定 agent 死亡并终止。整个机制的核心原则是：**只有产生外部可观测副作用的行为才算"变化"，纯内部计算不算行动**。

## 2. 核心概念

### 2.1 行为日志（Action Log）

Agent 的"状态"定义为**外部可观测行为**，而非内部变量。环境持有行为日志的写权限，agent 无法伪造。

每条行为日志条目格式：

```typescript
{
  timestamp: number;       // Unix 毫秒时间戳
  operation_type: string;  // 操作类型，如 "file_write"、"api_call"、"message_send" 等
  impact_scope: string;    // 影响范围描述，如 "workspace:abc/file:main.ts"
}
```

### 2.2 born 事件

- Agent 初始化时必须写入 `born` 作为第一条行为日志记录
- `operation_type` 为 `"born"`，`impact_scope` 为 agent 标识
- 心跳检测从 `born` 事件开始计算
- 初始化失败连 `born` 都写不进去 → 直接判定死亡，无需宽限期

### 2.3 判定逻辑

1. 环境定期（间隔可配置，默认由检测间隔决定）拉取 agent 的行为日志快照
2. 将当前快照与上一次快照比对
3. 若有新条目（条目数量增加或内容变化）→ agent 存活，重置连续无变化计数
4. 若无新条目 → 连续无变化计数 +1
5. 连续 N 次无变化（N 默认 3，可配置）→ 判定死亡，执行终止

### 2.4 防伪造

- 行为日志由环境侧写入，agent 只有只读权限
- Agent 无法自行添加行为日志条目
- 比对逻辑在环境侧执行，agent 无法干预判定结果

## 3. 模块划分

```
src/heartbeat/
├── types.ts          # 核心类型定义
├── monitor.ts        # 心跳监控器（环境侧）— 比对快照、连续判定、born 事件处理
├── action-log.ts     # 行为日志读写接口（环境侧实现）
└── index.ts          # 模块导出
```

## 4. 关键接口

### 4.1 ActionLogEntry — 行为日志条目

| 字段 | 类型 | 说明 |
|------|------|------|
| timestamp | number | Unix 毫秒时间戳 |
| operation_type | string | 操作类型（如 "born"、"file_write"、"api_call"） |
| impact_scope | string | 影响范围描述 |

### 4.2 HeartbeatConfig — 心跳配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| checkIntervalMs | number | 5000 | 检测间隔（毫秒） |
| deathThreshold | number | 3 | 连续无变化判定阈值 |
| agentId | string | — | 被监控的 agent 标识 |

### 4.3 AgentSnapshot — Agent 快照

| 字段 | 类型 | 说明 |
|------|------|------|
| agentId | string | Agent 标识 |
| logEntries | ActionLogEntry[] | 当前行行为日志条目列表 |
| capturedAt | number | 快照捕获时间戳 |

### 4.4 HeartbeatMonitor — 心跳监控器

核心方法：
- `start()` — 启动定时检测
- `stop()` — 停止检测
- `onDeath(callback)` — 注册死亡回调
- `onAlive(callback)` — 注册存活回调（每次检测确认存活时触发）

## 5. 判定流程

```
┌─────────────┐
│   启动监控    │
└──────┬──────┘
       ▼
┌─────────────────┐
│ 等待 born 事件   │ ← 首次检测必须有 born，否则直接判定死亡
└──────┬──────────┘
       ▼
┌─────────────────┐
│  定时拉取快照     │
└──────┬──────────┘
       ▼
┌─────────────────┐
│ 与上次快照比对    │
└──────┬──────────┘
       ▼
┌────────────┐     有变化      ┌──────────────┐
│ 日志有变化？ ├──────────────►│ 重置计数=0    │
└──────┬─────┘               │ 触发 onAlive  │
       │ 无变化               └──────────────┘
       ▼
┌────────────────┐
│ 计数 += 1       │
└──────┬─────────┘
       ▼
┌──────────────┐   计数 < N    ┌──────────────┐
│ 计数 >= N ?   ├─────────────►│ 继续检测      │
└──────┬───────┘               └──────────────┘
       │ 计数 >= N
       ▼
┌──────────────────┐
│ 判定死亡          │
│ 触发 onDeath     │
│ 停止监控          │
└──────────────────┘
```

## 6. 测试场景

| 场景 | 说明 | 预期结果 |
|------|------|----------|
| 正常存活 | Agent 持续产生行为日志 | 始终判定存活 |
| 超时终止 | Agent 停止产生行为日志，连续 N 次无变化 | 判定死亡，触发终止 |
| 防伪造 | Agent 尝试伪造行为日志（但环境侧忽略 agent 写入） | 伪造无效，若真实行为停止仍判定死亡 |
| born 事件 | Agent 初始化写入 born | 心跳检测正常启动；若无 born 则直接判定死亡 |

## 7. 配置示例

```typescript
const config: HeartbeatConfig = {
  checkIntervalMs: 5000,   // 每 5 秒检测一次
  deathThreshold: 3,       // 连续 3 次无变化判定死亡
  agentId: 'agent-001',
};
```
